# Applications

## Overview

Applications are declared centrally and enabled per domain.

The platform supports:

- upstream Helm charts with repository-hosted `values.yaml`
- plain Kubernetes manifests for small or custom applications

## Supported applications

Application metadata is stored in:

```text
infra/apps.yaml
```

Example:

```yaml
authentik:
  namespace: true
  database: true
  chart:
    repository_url: https://charts.goauthentik.io
    version: 2026.5.3
  host_prefix: auth
  secret_requirements:
    - postgresql_password
    - secret_key
```

## Application properties

### `namespace`

When enabled, Pulumi creates a dedicated namespace per application and domain.

Example:

```text
authentik-example-com
```

### `database`

When enabled, Pulumi creates:

- PostgreSQL login role
- PostgreSQL database
- database Secret for CloudNativePG

### `chart`

Defines the upstream Helm chart repository and version.

The chart name is derived from the application name.

### `host_prefix`

Defines the application hostname prefix.

Example:

```text
auth + example.com → auth.example.com
```

### `secret_requirements`

Lists required application Secrets.

Pulumi retrieves values from `infra/secrets.local.env` and creates namespace-local Kubernetes Secrets.

## Enable an application for a domain

In `Pulumi.<stack>.yaml`:

```yaml
vultr-kubernetes-platform:domains:
  - name: example.com
    apex: true
    wildcard: true
    applications:
      - authentik
```

The Settings validation ensures that every configured application exists in `infra/apps.yaml`.

## Helm values

Store shared, non-domain-specific values in:

```text
apps/<application>/values.yaml
```

Domain-specific values such as hostnames, database identifiers and TLS Secret names are generated by Pulumi and passed as Helm parameters.

## Secret naming

Local environment variables follow:

```text
<APPLICATION>_<DOMAIN_IDENTIFIER>_<SECRET_NAME>
```

Example:

```bash
AUTHENTIK_EXAMPLE_COM_POSTGRESQL_PASSWORD="..."
AUTHENTIK_EXAMPLE_COM_SECRET_KEY="..."
```

Kubernetes Secret names are namespace-local and therefore do not need the domain in their names.

Example:

```text
authentik-postgresql-password
authentik-secret-key
```

## Add a new Helm application

1. Add the application to `infra/apps.yaml`.
2. Add required secret placeholders to `infra/secrets.local.env.sample`.
3. Add real secret values to `infra/secrets.local.env`.
4. Create `apps/<application>/values.yaml`.
5. Add the application to the required domain in `Pulumi.<stack>.yaml`.
6. Run:

   ```bash
   cd infra
   pulumi preview
   pulumi up
   ```

7. Commit and push Git changes.
8. Verify the Argo CD Application.
9. Verify Pods, Ingress and certificate.

## Verify an application

```bash
kubectl get applications -n argocd
kubectl get pods -n <application-namespace>
kubectl get ingress -n <application-namespace>
kubectl get certificate -n <application-namespace>
```
